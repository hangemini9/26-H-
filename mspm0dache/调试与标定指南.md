# mspm0dache 调试与标定指南

本指南适用于 LP-MSPM0G3507、双路逐飞 DRV8701E、两台
MG513XP28_12V 电机和 13 PPR 霍尔编码器。当前固件使用 LaunchPad 板载
XDS110 和 Micro-USB 下载；外接八键板 SW1 接 PA10/BP33。build
`2026073005` 中启用 KEY1 独立测试：按键本地启动/停止底盘，不等待 MC02，
但仍不能代替物理急停。

## 1. 上电前必须确认

### 编码器只能向 MCU 输出不高于 3.3 V 的信号

- 两个编码器均使用稳定的 **5 V** 供电。
- 接入 LaunchPad 前，缓慢转动电机，用示波器或万用表分别测量四路
  A/B 原始信号；按推挽 5 V 输出处理，并让四路信号经过合适的
  5 V 转 3.3 V 单向电平转换器。MCU 侧高电平必须不超过 3.3 V。
- **5 V 推挽输出不得直连 MSPM0 GPIO。**

### 6S 电池不能直接驱动 12 V 电机

6S 锂电池标称约 22.2 V，满电约 25.2 V，而电机额定电压为 12 V。
电源链路必须为：

```text
6S 电池
  -> 主保险丝 + 可触及的物理总开关
  -> 足够电流能力的稳压 12 V 降压模块
  -> DRV8701E 电机电源
  -> 两台 12 V 电机
```

- DRV8701E 本身能承受较高电压，不代表 12 V 电机可以承受 25.2 V。
- LaunchPad 和编码器也必须使用各自正确的稳压电源。
- 控制地必须共地，但电机大电流不能经过 MCU 或编码器的细地线回流。
- 固件没有物理急停输入，因此必须保留可立即切断电机电源的总开关。
- **电机电源接通时禁止打断点或暂停 CPU。** CPU 停止后超时保护无法执行，
  PWM 定时器还可能停在高电平。带电测试只用 Expressions 动态观察，不使用断点。

## 2. 板载 XDS110 与 USB

把 J101 全部跳帽恢复到出厂安装状态，J102/J103 保持悬空，不向 J11 注入
外部 3.3 V。只需使用开发板自带的 Micro-USB 线连接电脑和 LaunchPad 的
板载 XDS110 USB 口。

在 VS Code 中运行任务 `Build and Flash MSPM0 (onboard XDS110)`，或执行：

```powershell
C:\ti\ccs\utils\bin\gmake.exe -C . flash
```

Ozone 不能使用 XDS110。需要动态写入变量时，用 CCS 调试器的 Expressions
视图；源码编辑和 Makefile 编译仍在 VS Code。

## 3. 编译、下载与调试变量

在 VS Code 中按 `Ctrl+Shift+B`，选择 `Build MSPM0 (TEST_MODE)`；也可在
工程根目录运行：

```powershell
C:\ti\ccs\utils\bin\gmake.exe -C . -j4
```

下载 `ticlang\mspm0dache.out` 后，在 CCS Expressions 中加入：

```text
g_test
```

调 PID、控制测试和截图都只使用这一个结构体。停车时可以修改
`duration_ms`、`target_rpm` 和 `left/right.kp/ki/kd`；左右轮下面的
编码器计数、转速、误差、PWM、积分和 PID 输出均为实时数据。

复位后必须确认：

```text
g_test.build_id == 2026073005
g_test.mode == 0
g_test.arm == 0
g_test.status == 0
PA12、PA13、PB4、PB1 均为低电平
```

## 4. 调试器下发命令的固定顺序

每次运动命令都严格按以下顺序写入：

1. 先填写全部参数。
2. 写 `g_test.arm = 1`。
3. **最后**写 `g_test.mode`。
4. 固件接收后会自动清除 `arm`。
5. 达到目标、发生故障或超时后，固件会停止并解除使能。

任何时候写 `g_test.mode = 0`，都会在最长 10 ms 内停止并解除使能。版本
`2026072504` 在解除使能时会把 PA12、PA13、PB4、PB1 四根控制线全部切换为
GPIO 低电平；每个 PWM 通道命令为 0 时也会单独切换为 GPIO 低电平。重新完成
断电测量前，不能把软件停机当作物理急停。

| mode | 功能 | 需要 `arm=1` |
|---:|---|:---:|
| 0 | 停止并解除使能 | 否 |
| 1 | 停止，仅观察编码器数据 | 否 |
| 2 | 清零左右编码器累计值 | 否 |
| 3 | 仅右轮，正向开环 PWM | 是 |
| 4 | 仅左轮，正向开环 PWM | 是 |
| 5 | 双轮正向开环 PWM | 是 |
| 6 | 双轮反向开环 PWM | 是 |
| 7 | 双轮按 `target_rpm` 闭环 | 是 |
| 8 | 低速黑线循迹 | 是 |

| status | 含义 |
|---:|---|
| -6 | 巡线传感器断连、采样停滞或连续丢线 100 ms |
| -5 | 必需的电机输出未能启动，或实际输出方向错误 |
| -4 | 必需的编码器无计数、停止计数或方向错误 |
| -3 | 参数非法 |
| -2 | 运动超时 |
| -1 | 未先置 `arm=1` 就请求运动 |
| 0 | 空闲 |
| 1 | 运行中 |
| 2 | 已完成 |
| 3 | 等待启动/确认新的有效巡线采样 |

固件安全限制：

- 开环诊断固定使用 15% PWM。
- 模式 3-7 单次最大 30000 ms；模式 8 总上限 120000 ms，MC02 第一问
  命令最多 20000 ms。
- 模式 7 的时长不能小于 2000 ms，闭环输出绝对上限为 40% PWM。
- 模式 7 要求两个编码器沿命令方向持续计数；状态 `-4` 时，
  `encoder_fault_mask` 的 bit 0 表示左轮、bit 1 表示右轮。
- 状态 `-5` 时，`output_fault_mask` 的 bit 0 表示左轮、bit 1 表示右轮。
- 每个车轮的首个 750 ms 编码器监督窗只在换向等待结束、实际 PWM 已恢复后
  开始；一旦开始就不会再暂停。之后若无持续运动，最多 750 ms 报错，非零
  反向输出则立即报错。模式 7 必须让 `encoder_verified_mask` 的左右两个
  bit 都通过完整监督窗，才能成功。
- 模式 7 运行期间不能直接改变方向或 PID 参数。
- 反向前会先撤掉 PWM，固定至少滑行 1000 ms，随后还必须确认低于 2 RPM；
  然后改变 DIR，再等待 10 ms 才恢复 PWM。编码器反馈不能缩短这 1000 ms。

`g_test.status` 只用于观察，不是控制变量；误改它不会暂停固件内部的超时和
故障保护。

## 5. 推荐调试与标定顺序

### A. 仅 MCU，不接电机电源

1. 断开 DRV8701E 的电机电源。
2. 编译、下载并复位。
3. 检查上述复位变量和 PA12、PA13，确认没有有效 PWM。

### B. 标定左右编码器 CPR 和方向

保持电机电源断开，编码器使用已验证的 5 V；四路 A/B 经电平转换后，
确认 MCU 侧高电平不超过 3.3 V。

1. 写 `g_test.mode = 2` 清零。
2. 写 `g_test.mode = 1` 进入观察模式。
3. 给左轮做标记，沿车辆前进方向精确手转输出轮一整圈。
4. 记录 `g_test.left.encoder_count`。
5. 再次清零，对右轮重复，记录 `g_test.right.encoder_count`。
6. 每侧至少重复数次，使用实测绝对值，而不是只按 13 PPR 理论计算。

2026-07-25 的四组十圈测量结果为：左轮平均 1467.475 counts/rev，右轮平均
1467.95 counts/rev；版本 2026072504 分别取左1467、右1468。更换编码器或
减速箱后需要重新测量。左右实测值分别写入
`chassis_config.h`：

```c
ENCODER_LEFT_COUNTS_PER_WHEEL_REV
ENCODER_RIGHT_COUNTS_PER_WHEEL_REV
```

车辆前进方向手转时，修正后的累计值应为正。若为负，只修改对应的
`ENCODER_*_REVERSED` 标志后重测，不要同时改多个方向标志来掩盖接错线。

慢速手转时 `g_test.left_invalid_transitions` 应接近零；若快速增加，应检查
噪声、上下拉配置和软件解码漏边沿。

### C. 不接电机电源，检查 PWM/DIR

1. 断开全部电源，用万用表蜂鸣档逐根确认：
   PA12/BP32 只到 PWM1，PB4/BP40 只到 DIR1，
   PA13/BP31 只到 PWM2，PB1/BP39 只到 DIR2。
2. 只连接 DRV 的 GND、PWM1、DIR1、PWM2、DIR2，保持电机 12 V 断开。
3. 只用 USB 启动，在 mode 0 测得 PA12、PA13、PB4、PB1 全部为 0 V。
4. 设置 `g_test.duration_ms = 2000`；开环诊断固定使用 15% PWM。
5. 按固定下发顺序运行模式 3，确认只有 PA12 输出 20 kHz、10% PWM。
6. 改回 mode 0，确认四根控制线都在 10 ms 内回到 0 V。
7. 再运行模式 4，确认只有 PA13 输出 PWM，并重复 mode 0 全低测试。
8. 用示波器确认 DIR 只在 PWM 已撤掉时改变，并符合 1000 ms 滑行和
   10 ms DIR 建立时间。

### D. 悬空车轮，首次电机测试

1. 固定底盘，使两个驱动轮都离地。
2. 先把降压模块输出调到实测 12.0 V，再连接 DRV 电机电源。
3. 从 `open_pwm = 10` 开始，不要从 30% 开始。
4. 分别运行模式 3、4，再短暂运行模式 5。
5. 正向 PWM 必须使对应车轮向车辆前进方向转动，同时修正后的编码器计数增加。

若电机方向错误，只修改对应的 `MOTOR_*_OUTPUT_REVERSED`，或明确交换该电机
两根动力线，并记录实际采用的方案。

### E. 转速闭环和 PID

只有 CPR、编码器方向和电机方向全部正确后才调 PID。

1. 设置 `target_rpm = 40`、`duration_ms = 5000`。
2. 按固定顺序运行模式 7。
3. 同时观察 `g_test.left/right` 中的 `rpm`、`error_rpm`、`pwm`、
   `integral` 和 `pid_output`。
4. 只在停止状态修改 `g_test.left/right.kp/ki/kd`，新参数会在下一次
   模式 7 启动时生效。

初始参数仅为起点：

```text
Kp = 0.7
Ki = 20.0
Kd = 0.0
控制周期 = 0.010 s
```

若状态为 `-4`，先停止并检查方向标志、接线、供电、信号质量或机械卡滞，
不要通过增大 PWM 绕过故障。固件内部 40% 闭环上限不可通过 WATCH 修改。
最终左右 PID 参数应记录到 `AGENT.MD`。

### F. 落地距离与转向标定

距离和转角命令模式暂缓，等编码器计数与模式 7 PID 调试通过后再加入。

### G. KEY1 独立启动

build `2026073005` 只使用八键板的 SW1。接线：

- `SW1 -> PA10/BP33`；
- `GND -> 系统 GND`；
- `VCC -> LaunchPad 3V3`，禁止接 5V；
- `SW2-SW8` 均不接。
- J21、J22 保持在 `BP`/BoosterPack 一侧。

PA10 使用 MSPM0 内部上拉，松开为高电平、按下接地为低电平。固件每
10 ms 轮询并进行 40 ms 消抖：

VCC 悬空时用户实测松开只有 2.16 V、按下 0 V；松开电平不合格。VCC 改接
3V3 后，必须先复测松开约 3.3 V、按下约 0 V，再接通电机电源。

1. 按下并松开 KEY1，本地倒计时 3 秒，倒计时期间电机保持关闭；
2. 倒计时结束后仍须在 500 ms 内收到连续 5 个启动后新采集的有效红外
   样本，才允许 `Motor_Arm()`；
4. 启动后先以 30 RPM 基速慢行 1 秒，再平滑升至前 300 mm 的 55 RPM
   限制，随后Q1正式场地直线基速最高 143 RPM、弯道基速最低 110 RPM，
   转向 Kp 12、Kd 6；本地运行总超时固定 20000 ms；
4. 倒计时或运行期间再按一次 KEY1，立即取消/停车；
5. `STANDALONE_KEY1_START=1` 是当前临时选择；以后需要 MC02 时改为 0，
   再恢复 PREPARE/READY/START 为唯一启动授权。

SW2-SW8 与板载 S2 当前均无功能，所以 K7/K8 本地停车还未实现。物理总
开关必须始终可触及。

### H. 蓝牙暂时停用

JDY-31 已拔掉。build `2026073005` 不生成 UART0，也不编译或调用
`bluetooth.c`；PA10 已改作 SW1。蓝牙源文件和电脑脚本仅作为以后恢复时的
参考保留，当前固件不能接收任何蓝牙命令。

### I. 幻尔 8 路巡线与低速循迹

`2026073005` 在已验证的传感器采集上通过 KEY1 本地启动比赛循迹模式 8：

1. 电机电源保持断开，先不要接 PB2/PB3；
2. 模块 `5V` 接稳定 5 V 辅助电源，`GND` 接系统公共地；
3. 模块单独上电后，分别测 `SCL`、`SDA` 对 GND 的空闲电压；
4. 两路都不高于 3.3 V 时，断电后接 `SCL -> PB2/BP9`、
   `SDA -> PB3/BP10`；若任一路高于 3.3 V，必须加双向 I2C 电平转换；
5. 下载固件，保持 `g_test.mode = 0`，在 WATCH 展开 `g_test.line`；
6. `connected = 1` 且 `sample_sequence` 持续增加，表示 I2C 通信正常；
7. 固定安装高度并按模块 KEY 完成“背景长按学习、目标线短按学习”；
8. 逐个移动 S1-S8，记录 `state` 位序、`analog[0..7]`、
   `threshold[0..7]`，并确认车头朝前时 S1 在物理左侧还是右侧。

已实测确认白底 `state=0`、S1 黑线 `state=1`、S8 黑线 `state=128`，
即 bit0=S1（车左）、bit7=S8（车右），置位代表黑线。

首次运动检查必须架空驱动轮，同时保持传感器与测试纸的标定高度，然后
按下 KEY1 启动。

1. 黑线位于 S4/S5 时两轮转速应接近相等；移向 S1 时左轮变慢、右轮变快；
   移向 S8 时相反；
2. 巡线位置先以 0.25 系数低通后再参与弯道调速与 PD 计算，避免数字通道
   切换造成速度阶跃。短暂丢线的前 50 ms 保持原目标，随后才按最后一次
   线路所在方向以 45 RPM 基速和 28 RPM 差速搜线；300 ms 内重新检测到线
   则恢复，持续超过 300 ms 才停车并保留 `status=-6`。I2C 断开或数据停止
   更新仍立即撤掉目标，并在 100 ms 内报错停车；
3. 再按一次 KEY1 必须能提前停车。

模式 8 延用模式 7 的轮速 PID、编码器监督、PWM 限幅和到时停车。正式场地
由两段 1.5 m 直线和两个半径 0.5 m 的半圆组成，中心线总长
`2×1.5+2π×0.5=6.1416 m`，外廓约 2.5 m × 1.0 m。65 mm 轮径下，
20 秒纯匀速理论下限约 90.2 RPM；当前正式版Q1使用 143 RPM 直线基速和
110 RPM 弯道最低基速。比赛时把车头阵列放在起点
横向长黑线上，按 KEY1 启动；程序先倒计时 3 秒并确认连续 5 个新红外采样，
再以 30 RPM 慢行；起点横线后的前 100 mm 左右轮保持相同目标，随后才启用
灰度重心转向并逐步提速。完成一圈后，编码器航向累计和距离只负责进入停车
流程：程序以 60 RPM 继续循迹 150～250 mm，要求普通直线连续 8 个新采样
保持居中且只亮 1～2 路，然后真正零 PWM，待双轮降到 2 RPM 以下，再以
左右相同的 25 RPM 低速倒车。倒车时统计最近 120 ms 的通道位图并集；
并集至少覆盖 4 个不同通道、左右半区均出现并连续确认 2 个新采样，才认定
循迹模块到达终点横线并立即失能停车。倒车超过 400 mm 或 6 秒仍未找到横线
则按超时安全停车，不允许继续第二圈。当前距离
换算使用 65.0 mm 轮径及左右 1467/1468 CPR，首次场地测试必须用尺测量实际
停车偏差和总用时，再按实测结果修正。传感器、编码器或输出发生故障仍会提前停车；
再按 KEY1 也可随时提前停止。

204.7 mm 前后轴距不进入理想两轮差速公式，但会通过万向轮阻力和打滑影响
实际转向，因此最终轮距必须在整车装配并加载后实测标定。
